# How assessment works in this programme

Every daily notebook contains a **Section G** automated assessment.

1. **Visible checks** — in the notebook. They report `PASS`/`FAIL` per behaviour
   and a final score instead of stopping at the first failure, so the notebook
   always runs top-to-bottom. A `FAIL` before you implement an exercise is expected.
2. **Unseen variants** — the same behaviours re-tested with different dates,
   tickers, values, row orders and deliberately dirty inputs (empty frames,
   duplicate dates, negative prices, renamed/MultiIndex columns).
   Hard-coded answers and copy-pasted video code fail these by design.
3. **Explanation checks (Section H)** — at least one "explain this in your own
   words / what changes if…" answer per day is reviewed before the next day unlocks.
4. **Milestone reviews (Days 4, 7, 9)** — code quality, tests, and documentation
   are reviewed together; the capstone (Day 13) is defended in a written report.

Solutions are **not** in the learner notebooks. Progressive hints are.
A separate solutions notebook is produced only on explicit request, after an attempt.
