# D16 — Live harness running

## Objective

Ship a scheduled bot that trades the Week 10 risk policy using the *same signal code* as the backtest, logs every decision (including doing nothing), and rebuilds a dashboard from its own logs.

## Teaches

A live bot is a boring scheduling problem wearing a finance costume. The failure modes are operational - stale data, duplicate runs, timezone bugs, silent exceptions - and every one of them looks like a strategy loss if you are not logging carefully.

## Build

1. **`live/bot.py`** implementing the daily cycle in [spec/signal-generator-spec.md](../spec/signal-generator-spec.md): refresh → signal (imported `generate()`) → risk policy → diff → orders → log → dashboard.
2. **Broker adapter**: `live/broker_paper.py` (deterministic fills at last close ± configured slippage; the default) or `live/broker_alpaca.py` (real paper fills; keys from environment variables only).
3. **`live/log/YYYY-MM-DD.json`** per day, with the fields from the spec - including `skipped` and `errors`.
4. **`live/equity.csv`**: date, equity, cash, gross exposure, positions count, notes.
5. **`live/dashboard.html`** regenerated by script from the logs, with a "did the bot run today?" panel and a backtest-vs-live overlay.
6. **`live/README.md`**: adapter, schedule, how to read a log day, how to stop the bot (`live/STOP`).

## Required behaviours (test them, don't assume them)

- [ ] Idempotent: two runs on one day produce one set of orders
- [ ] Stale-data guard: last bar > 4 calendar days old → skip and log
- [ ] Kill switch: `live/STOP` present → no new orders, positions untouched
- [ ] Missing symbol in the universe → loud failure, not a partial book
- [ ] Crash mid-run → next run recovers without duplicating orders

## Definition of done

- [ ] `live/bot.py` exists and runs on a schedule without manual intervention
- [ ] 7+ consecutive daily logs, each with signals, targets, orders, fills, equity, skipped, errors
- [ ] `live/dashboard.html` generated from logs (grep it for hand-edited numbers: there should be none)
- [ ] Five required behaviours above are each demonstrated once and noted in `live/README.md`
- [ ] The signal comes from `strategies/<id>/signal.py::generate` - no re-implementation anywhere in `live/`
- [ ] No parameter or rule changes since the spec fingerprint recorded in the logs

## Evidence

`live/bot.py` · `live/config.json` · `live/log/` · `live/dashboard.html`
