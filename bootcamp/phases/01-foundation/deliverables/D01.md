# D01 — Data pipeline + validation report

## Objective

Stand up the fetch → cache → validate pipeline that every later week depends on, and prove with a written report that you know what is in your data.

## Teaches

Raw prices are not data yet. Until you have checked the index, the gaps, the duplicates and the outliers, every number built on top of the file is unverified. This is one deliverable and one idea: **validate before you measure.**

## Build

1. Use `kit/data_fetcher.py` (do not rewrite it this week) to cache 8-10 instruments:

   ```bash
   make data SYMBOLS="SPY QQQ IWM TLT IEF GLD EEM EFA DBC UUP" START=2005-01-01
   ```

2. Run `make validate`. Every symbol must end in `ok`, or have a written reason why not.
3. Inspect `data/<SYMBOL>.meta.json` for at least three symbols: provider, fetch time, row count, date range, sha256.
4. Tamper test: copy a CSV, corrupt three rows (a duplicate date, a 10x close, a `high < low`), run validation, confirm all three are caught. Document the output.
5. Write `reports/data-validation.md`:

   | symbol | rows | first | last | issues | warnings | source | verdict |
   | --- | --- | --- | --- | --- | --- | --- | --- |
   | (one row per symbol, filled in) |

   Plus, per symbol with warnings: the warning, your decision (accept / investigate / exclude), and the reasoning in one sentence.

## Definition of done

- [ ] 8+ symbols cached, each with a `.meta.json` sidecar
- [ ] `make validate` exits 0 (or every failure is documented as excluded, with a reason)
- [ ] The tamper test is documented with its actual output
- [ ] `reports/data-validation.md` exists with the coverage table and per-symbol decisions
- [ ] You can answer: which symbol would you distrust, and why?
