# D04 — Viral debunks #2-3 + graveyard entries

## Objective

Repeat the debunk loop twice more - once on a claim you believe, once on a claim built on a tiny sample - and file all three claims in the graveyard with precise causes of death.

## Teaches

Most "edges" are one of three problems: a definition problem (win rate is not edge), a cost problem (turnover eats the gross return), or a sample-size problem (the evidence is too thin to be evidence). Naming which one, every time, is the skill.

## Build

1. **Debunk #2** (`reports/debunks/debunk-02.md`): the claim you most believe. Write your prediction first (which killer, how much), then test. If it survives, mark `survives (partially)` and say what would have to change for it to be an edge.
2. **Debunk #3** (`reports/debunks/debunk-03.md`): the thinnest-sample claim. Quantify the sample: independent bets, win-rate confidence interval, and what the claim would need to look like to count as evidence.
3. **Graveyard**: three entries in `graveyard.md`, each using a taxonomy cause: `no edge`, `cost death`, `look-ahead illusion`, `overfit`, `regime dependence`, `data problem`, `operational death`, `thesis wrong`, `insufficient sample`.
4. **Reflection** (one paragraph per debunk, at the bottom of each file): would this have fooled you before the check? Which of the three checks do you skip when you are tired?

## Definition of done

- [ ] Two more debunk files, both following the template
- [ ] Three graveyard entries with taxonomy causes and evidence links
- [ ] Debunk #2 has a written pre-test prediction and a comparison to the outcome
- [ ] Debunk #3 includes an explicit sample-size computation (bets, not rows)
- [ ] At least one reflection paragraph that names a bias you actually have
