# M2 — Backtest engine (end of Week 4)

## Pass condition

> Take a fresh idea from data to tearsheet + verdict end-to-end in under 30 minutes.

Verbatim from the course registry. The timer log for the passing run is referenced from
`engine/README.md` or the strategy's `verdict.md`.

## What it proves

That you own the measurement apparatus. Not that the idea worked - that you can find out
whether it worked, quickly and repeatably, with costs and out-of-sample baked in. From here
on, "I think this might work" costs you half an hour, not a weekend.

## Supporting requirements

- Contract suite green: `make test-contract E=engine.backtest`
- Time-travel test and signal-shift premium test in `tests/test_lookahead.py`
- Tearsheets generated by `engine/tearsheet.py`, never hand-written
- `meta.json` on every result carries spec and data fingerprints

## Fail path

If the 30-minute run fails, the fix is almost always friction, not ability:

| Symptom | Fix |
| --- | --- |
| writing the spec takes 15 minutes | keep `config/<id>.json` next to a filled-in example; copy and edit |
| the signal file needs engine internals | the SIGNAL contract is `generate(prices, params)`, nothing else |
| tearsheet missing sections | generate from the template programmatically; stop editing markdown by hand |
| verdict writing drags | copy `shared/templates/verdict.md` before you start the timer |

Repeat with a second fresh idea within 48 hours. Two consecutive overruns means you are still
building during the timed run - build first, then time it.

## Remediate before Week 5

Phase 3 runs six strategies through this engine. If M2 failed, run one more untimed
end-to-end pass and fix everything that felt manual before starting the factory. Building six
strategies on a shaky engine produces six artefacts you cannot trust and a Week 6 audit that
falls apart.
