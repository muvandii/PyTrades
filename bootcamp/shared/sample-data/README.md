# sample-data/ - the laboratory (simulated, with known answers)

Six series, generated by `bootcamp/tools/make_sample_data.py` with a fixed seed, plus
`truth.json` describing exactly what was planted in each one.

**These are not market returns.** They exist so that:

1. You can run the whole pipeline with no network access (Week 1 does not care where bars come from).
2. Some exercises have *known* answers: the trend lab really does contain momentum, the
   pair lab really does contain a cointegrated period, the MR lab really does die on costs.
   You can check whether your code found what is definitely there - impossible with real markets.

## The labs

| File | Planted property | Expected outcome | Used for |
| --- | --- | --- | --- |
| `LAB_TREND.csv` | 120-day drift regimes + positive autocorrelation | trend/momentum works OOS | Weeks 3-6 trend work |
| `LAB_RANDOM.csv` | random walk, no autocorrelation | buy-and-hold beats every rule | Week 1 baselines, Week 6 luck calibration |
| `LAB_MR.csv` | OU spread, half-life ~28 bars | gross Sharpe ~0.9, crosses zero near 20 bps | Week 5 reversion, cost-death autopsy |
| `LAB_PAIR_A/B.csv` | cointegrated, **structural break at bar 2080 (~80%)** | coint passes in-sample, dies at the end | Week 6 + Week 8 pairs |
| `LAB_VOL.csv` | vol clustering, lower returns in high vol | vol targeting improves Sharpe | Week 7 TSMOM, Week 10 sizing |

## How to use them honestly

```bash
cp sample-data/LAB_*.csv data/          # once; then treat them like any cached series
make validate                            # note what the validator flags
```

Rules:

1. Treat them exactly like real bars - same validation, same costs, same verdict template.
2. Any verdict built on a lab series must say so in its first line:
   `**Data: LAB_MR (simulated, planted half-life 10 bars) - code validation, not market evidence.**`
   A lab verdict grades your *pipeline*. It is not evidence about a market, and Week 13 you
   will be embarrassed if it reads like one.
3. `truth.json` is an answer key to check your *process* against. Read it after you write
   your verdict, not before - otherwise you are not testing your process, you are copying.
4. The graded debunks (D03, D04) and every strategy verdict need real bars. Labs are for
   smoke tests, classroom demos, and offline fire drills.
